# Checkpoint and Handoff

Version 0.4.0. Python 3.9+ and Git preserve task state as verified Markdown/JSON bundles. Codex CLI provides optional usage collection and separate bounded workers. No API key or paid fallback is required.

Install with `python install.py --skills-dir ~/.agents/skills --repair`. Run `python setup.py status --project /absolute/project` before setup. Reuse an existing binding; for a new project inspect its queues/stores, then explicitly supply `--task TASK --project-id OWNER/REPOSITORY` to `python setup.py setup --project /absolute/project`. Authenticate Codex and GitHub independently on each device. New setups reserve 20% of each applicable account allowance. To migrate an existing reserve, pass `--reserve 20`. Existing stops require reviewed resume.

Setup preserves customized hooks, checks managed installation hashes and reuses the existing native service. Open Codex `/hooks` to review and trust definitions; native trust is never granted by setup. Run setup/status again to see collection freshness and hook receipts. Status is evidence about collection, not proof that every native event was delivered.

On Windows, use PowerShell `./bootstrap.ps1 -Repository OWNER/REPOSITORY -Project C:\path\to\checkout`. The script resolves the actual checkout, checks its remote, requires device-local GitHub/Codex login, and calls the same setup workflow. An existing binding is reused. For a new binding also provide `-Task TASK -ProjectId OWNER/REPOSITORY` after inspecting existing queues.

At meaningful boundaries, maintain `.checkpoint/input.json` with the objective, decisions, completed work, actual checks and next action. See [task template](skills/task-checkpoint/assets/task-template.json), [operator guide](skills/task-checkpoint/references/operator.md), [routing](skills/task-checkpoint/references/router.md), and [automation guide](skills/task-checkpoint/references/automation-v04.md). A background collector cannot reconstruct unsaved conversation decisions.

The optional `routing.work_packages` list is the bounded plan. An agent supplies semantic work packages at the start of substantial work; the runtime validates dependencies/bounds, selects ready work and qualified model/effort, and dispatches one reviewed contract through the existing router. Approval expires within 24 hours; source changes require review before the next package. Qualification is specific to tools, privacy and task class. Lower effort can be a separate qualified worker on the same model. Relative cost settings are estimates; unknown usage savings remain unknown. No automatic desktop model switch is claimed.

Private transfers use immutable GitHub release assets in the configured private project repository. Source sync is separate. Every bundle contains exact manifest hashes, project/task identity, source revision, latest generation and previous valid generation. The same native collector can automatically receive into quarantine when explicitly configured; receive verifies source revision/identity/manifests and keeps source drift pending. Explicit adoption and fresh resume are separate. Receive verifies and quarantines data; permissions, native credentials and ownership are never imported, and no worker starts. See the automation guide for commands and recovery.

Support matrix: macOS 0.4 has native maintainer verification for collector/threshold preservation, deduplication, durable recovery stop, reviewed resume, active-folder SessionEnd delivery and native collector-to-planner dispatch of a qualified public JSON contract. Concurrent maintainer evidence records native Windows 0.3 Task Scheduler collection, synthetic threshold/readback, deduplication, reviewed resume and Stop delivery;97/101 tests passed with four platform-dependent limitations. Version 0.4 onboarding/planner/transport and real two-device transfers still need native Windows verification. Scheduler generation and failure/rollback also have simulation coverage. Separate Sol/Luna CLI workers have narrow public tool-free JSON qualification only. General code/private-data qualification, local/free execution, API budget telemetry, attributable savings and changing the active desktop model remain unverified or unavailable.

Run `python -m unittest discover -s tests -v`. Tests use synthetic low usage; they never deliberately exhaust allowance. Original private historical evidence is not part of this clean-history public distribution.

Upgrade: checkpoint and release ownership, run setup/status, then setup/repair. Modified managed files are preserved for comparison. Prior managed source is archived under `.agents/skills/.task-checkpoint-rollback/`. Rollback: uninstall only unchanged managed skill, extract the reviewed previous archive to the skills directory, then run its status/setup procedure. Keep private `.checkpoint/` state and use matching runtime format; rollback never restores over working files.

Uninstall native collection first using `monitor.py --state STATE uninstall-service`; remove owned global hooks with `account.py --state STATE uninstall --codex-home PROFILE`; then `python install.py --skills-dir SKILLS --uninstall`. Review customized files manually. Private state and Git history remain.

Releases are generated by `python release.py --output /temporary/release.zip` from the exact [allowlist](public-export.json). Repeated export from identical sources is byte-identical and includes `PUBLIC-MANIFEST.json`. Review the complete exported tree and run its tests before creating a clean-history public repository or updating an existing public mirror. Never copy private Git history, checkpoints or raw logs. Preserve the MIT license notice.
